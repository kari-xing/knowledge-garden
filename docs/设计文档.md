## 1. 项目概述

**一句话定位**：融合笔记管理、AI 自动加工与知识图谱可视化的个人知识操作系统——把知识"种"进去，AI 帮你浇水施肥，让知识像花园一样自然生长。

### 1.1 核心差异化卖点

| 卖点 | 说明 | 对应模块 |
|---|---|---|
| ① 自动知识关联 | 新笔记写入后自动与已有知识建立语义关联，AI 生成"为什么有关联"的理由 | notes + ai_pipeline + graph |
| ② 动态知识图谱 | D3.js 力导向图实时呈现隐性知识网络，支持拖拽/缩放/路径探索 | graph 前端 + graph 后端 |
| ③ 知识生命周期游戏化 | `种子→生长→成熟→枯萎` + 间隔重复复习 + 花园看板，形成留存闭环 | garden + review |

### 1.2 设计原则（实现时严格遵循）

1. **零成本归档**：记录只需"写"一件事，标签/摘要/关联全部由 AI 完成，可后置修正。
2. **被动发现**：关联、复习提醒、枯萎预警由系统主动推送，而非用户主动查找。
3. **渐进增强**：AI 能力不可用时（DeepSeek 无 Key / Ollama 未启动），系统降级为纯笔记管理仍可完整使用。
4. **Provider 抽象**：默认 DeepSeek 云端推理，可切换 Ollama 本地；LLM 与向量存储均做 Provider 抽象。

## 3. 核心概念与算法

### 3.1 知识生命周期状态机

```
                AI 流水线完成            累计复习 ≥ 3 次
   ┌──────┐ ────────────────► ┌────────┐ ─────────────► ┌────────┐
   │ seed │                   │ growing│                │ mature │
   └──────┘                   └────────┘                └────────┘
      ▲                           │                        │
      │  复习恢复(wilted→growing)  │ 超过30天未复习          │ 超过30天未复习
      └────────────────────────── ▼                        ▼
                              ┌────────┐ ◄─────────────────┘
                              │ wilted │
                              └────────┘
```

| 状态 | 含义 | 图谱表现（前端） | 实现位置 |
|---|---|---|---|
| seed | 刚创建，AI 处理中 | 琥珀色发光/呼吸动画 | `create_note` 初始值 |
| growing | 处理完成，持续生长 | 绿色 | `ai_pipeline` 完成后置为 growing |
| mature | 已复习 ≥ 3 次（阶段 ≥ 3）| 蓝色 | `review_service.apply_review` |
| wilted | 超过 30 天未复习 | 灰色半透明 | `tasks.scheduler.scan_wilted` |

### 3.2 间隔重复复习算法（艾宾浩斯变体）

```
复习间隔（天）：阶段 1→2→3→4→5 分别对应 1 / 3 / 7 / 15 / 30 天
remember（记住了）：stage_after = min(stage_before + 1, 5)
fuzzy（模糊）    ：stage_after = max(stage_before - 1, 1)
next_review_date = today + REVIEW_INTERVALS[stage_after]
```

- 每次复习写入 `review_logs`（含 stage_before/after 与 result），用于未来统计与连续天数。
- `status_after` 同步生命周期：wilted → growing（复活）；阶段 ≥ 3 时 seed/growing → mature。
- 到期判定：`next_review_date <= today`（见 `/garden/review-today`）。
- 实现：`backend/app/services/review_service.py`，间隔表由配置 `REVIEW_INTERVALS_JSON` 提供。

### 3.3 AI 处理流水线（异步 + 优雅降级）

```
保存笔记 → ①生成标题(若为空) → ②生成3-5个标签 → ③生成一句话摘要
        → ④生成向量写 ChromaDB → ⑤向量检索Top5相似
        → ⑥LLM生成关联理由 → ⑦写入 note_relations(无向去重)
        → ⑧状态 seed→growing、processing→done，刷新统计
```

- **执行方式**：`POST /notes` 同步保存返回 201 后，由 FastAPI `BackgroundTasks` 异步执行（不阻塞写接口）；`USE_ARQ=true` 时可切换到 Redis 队列。
- **每步独立容错**：LLM/向量任一不可用时自动跳过（标题用正文首行兜底、标签保留用户手工指定、关联为 0 条），笔记 CRUD 完全不受影响。
- **任务追踪**：每次处理创建 `ai_jobs` 记录（pipeline/regenerate/import 三种类型），前端通过 `processing_status` 每 3s 轮询，失败可手动"重新处理"。
- **降级闭环验证**：无 LLM 服务环境下，笔记创建后 `processing_status=done`、`status=growing`、手工标签生效，全链路正常。

### 3.4 混合检索（RRF 融合）

```
引擎1 全文：PostgreSQL ILIKE 匹配 title/content（中文未装分词时的兜底方案）
引擎2 语义：查询文本嵌入 → ChromaDB topK（不可用时跳过）
RRF 融合：score(d) = Σ_{engine} 1 / (k + rank_engine(d))，k = 60
返回：note + score + matched_fields(title/content/semantic) + snippet
```

- 前端可切换 `mixed / lexical / semantic` 三种引擎（`/search?engine=`）。
- 当 ChromaDB 不可用：semantic 返回空，mixed 退化为纯 lexical。
- 实现：`backend/app/routers/search.py`；`snippet` 由 `utils.make_snippet` 围绕命中位置截取。

### 3.5 图谱最短路径

- 建模：无向加权图，边权 `distance = 1 - similarity_score`（越相似"距离"越近）。
- 算法：**BFS**（按层扩展，天然保证跳数最少），重建节点序列 + 边序列 + 总距离。
- 前端路径模式：依次点击两个节点 → 请求 `/graph/path` → 高亮路径边（琥珀色加粗）。
- 实现：`backend/app/routers/graph.py::graph_path`。

### 3.6 标签配色

- 新标签创建时从 Tailwind 500 色阶调色板（10 色）**轮询取色**（`utils.next_color`）。
- 图谱节点颜色 = 主标签（首个标签）颜色；无标签默认 slate-400。
- 标签支持重命名/改色/合并/删除（`/tags` 模块）。

## 4. 数据模型

> 全部为 PostgreSQL 表，由 SQLAlchemy `Base.metadata.create_all()` 在应用启动时自动建表（幂等），模型文件见 `backend/app/models/`。

### 4.1 表结构一览

| 表 | 关键字段 | 用途 |
|---|---|---|
| `users` | email(唯一)、password_hash、display_name | 用户与认证 |
| `tags` | user_id、name、color | 独立标签实体（支持配色/合并） |
| `notes` | user_id、title、content、summary、status、processing_status、last_reviewed_at、search_vector(计算列) | 笔记主表 |
| `note_tags` | note_id、tag_id（复合主键） | 笔记↔标签多对多 |
| `note_relations` | user_id、source_note_id、target_note_id、similarity_score、relation_reason、source | 图谱无向边（AI 自动/每日/手动） |
| `review_schedule` | note_id(唯一)、review_stage、next_review_date | 每篇笔记一条复习计划 |
| `review_logs` | note_id、stage_before、stage_after、result | 复习历史（统计/连续天数） |
| `ai_jobs` | note_id、job_type、status、pipeline_version、error_message | AI 任务追踪 |
| `user_garden_stats` | total_notes/total_tags/total_relations/streak_days | 花园统计（写时对账） |

### 4.2 关键约束与索引

- **生命周期/处理状态**：`notes` 表 CHECK 约束限定 `status`（seed/growing/mature/wilted/archived）与 `processing_status`（pending/processing/done/failed）。
- **无向边去重**：`note_relations` 用 `CHECK (source_note_id < target_note_id)` + `UNIQUE(source_note_id, target_note_id)`，保证 `source < target` 排序存储。
- **级联删除**：所有子表外键 `ON DELETE CASCADE`，删除笔记自动清理标签绑定/关联/复习/任务。
- **全文检索**：`notes.search_vector` 为持久化计算列 `to_tsvector('simple', title || ' ' || content)`（预留 zhparser 升级位）。
- 主键统一 UUID v4（`models/base.py::UUIDMixin`）。

### 4.3 向量存储（决策 D1：唯一来源 = ChromaDB）

```
Collection: knowledge_garden（余弦距离空间）
id       = note_id（str）
document = title + "\n" + summary + 正文前 2000 字
metadata = { user_id, title, tags, status, note_id }
多用户隔离：query 时 where={"user_id": str(user_id)}
```

- 向量**只存 ChromaDB**，PostgreSQL 不存 embedding（避免双写一致性问题）。
- 普通编辑仅更新元数据；正文变更需"重新处理"才重建嵌入（前端可选 reprocess）。
- 删除笔记时调用 `collection.delete(ids=[note_id])` 级联清理（ChromaDB 不可用时静默跳过）。

## 5. API 设计

### 5.1 通用约定

- Base URL：`/api/v1`；鉴权：`Authorization: Bearer <JWT>`。
- 响应统一包裹：`{ "code": 0, "data": ..., "message": "ok" }`（错误时 code 非 0 或 HTTP 错误 + `detail`）。
- 错误码语义：0 成功 / 400 参数 / 401 未认证 / 403 无权限 / 404 不存在 / 409 冲突 / 500 内部。
- 分页：`page` / `page_size`（默认 20，上限 100），响应含 `total`。

### 5.2 接口清单（已实现 20 个端点）

| 模块 | 方法与路径 | 说明 |
|---|---|---|
| 认证 | `POST /auth/register`、`POST /auth/login` | 注册 / 登录，返回 JWT |
| 笔记 | `GET /notes`、`POST /notes` | 列表（page/status/tag/q 筛选）、创建（触发 AI 流水线） |
| 笔记 | `GET/PUT/DELETE /notes/{id}` | 详情（含关联+复习状态）/ 更新 / 删除 |
| 笔记 | `POST /notes/{id}/reprocess` | 手动重新触发 AI 处理 |
| 笔记 | `POST /notes/{id}/review` | 复习（remember/fuzzy），推进阶段 |
| 检索 | `GET /search` | 混合检索（q/tag/engine/page） |
| 图谱 | `GET /graph/nodes`、`/graph/links`、`/graph/path` | 节点 / 边 / 最短路径 |
| 花园 | `GET /garden/dashboard` | 看板聚合（种子/枯萎/复习/统计/关联/趋势） |
| 花园 | `GET /garden/seeds`、`/garden/wilting`、`/garden/review-today` | 三个子模块 |
| 标签 | `GET /tags`、`PUT/DELETE /tags/{id}`、`POST /tags/merge` | 列表/重命名改色/删除/合并 |
| 导入 | `POST /import/text`、`POST /import/pdf` | txt/md 批量 / PDF(≤20MB) |
| 系统 | `GET /health` | 存活检查 |

### 6.3 状态与缓存策略

- **服务端数据走 TanStack Query**：`queryKey` 按筛选参数组织（`['notes', {page,status,tag,q}]`），写操作后 `invalidateQueries` 失效刷新。
- **AI 处理轮询**：`useNoteProcessing` 在 `processing_status ∈ {pending, processing}` 时每 3s 刷新详情，完成后自动停止并失效相关缓存。
- **本地状态走 zustand**：auth（localStorage 持久化）、toast、深色模式。
- **乐观更新**：复习按钮本地立即反馈，失败 toast 回滚提示。

### 6.4 关键交互实现

- **编辑器自动保存**：`title/content/summary/tags` 任一变化 → 2s 防抖 → `PUT /notes/{id}` → 顶部"已保存/保存中"状态指示。
- **快速捕获**：全局 `Ctrl+Shift+K` 唤起模态框 → 创建草稿笔记 → 跳转详情页；提交后 AI 自动加工。
- **D3 图谱**：`useForceGraph` 为纯函数（`buildSimData` + `createSimulation`），`GraphCanvas` 负责渲染与事件，规避 D3 与 React DOM 管理冲突；节点半径∝关联度、颜色∝生命周期、种子节点带呼吸光环。
- **路径探索**：路径模式下依次点选两个节点 → 请求 `/graph/path` → 路径边琥珀色高亮。
- **视觉规范**：花园主题——主色 emerald-500（生长）、辅助 amber-500（种子）、sky-600（成熟）、slate-400（枯萎）；支持深色模式（`dark` class 切换）。

## 7. 后端设计

### 7.1 模块划分（`backend/app/`）

```
main.py      应用入口：lifespan 建表 + 启动调度 + CORS + 路由挂载
routers/     auth / notes / search / graph / garden / tags / imports
services/    ai_pipeline（异步流水线）/ review_service（复习算法）
             tag_service（标签解析同步）/ stats_service（统计对账）
tasks/       scheduler（每小时枯萎扫描 + 每日关联发现）
models/      SQLAlchemy 模型（含原有用例）
schemas/     Pydantic v2 请求/响应模型（与前端 TS 类型一一对应）
llm/         DeepSeek / Ollama / OpenAI 兼容 Provider 抽象
vector/      ChromaDB 存储抽象（决策 D1）
```

### 7.2 关键设计决策（实现层面）

1. **异步 + 防懒加载**：所有查询显式 `selectinload(Note.tags)`；新建笔记时把标签解析后**传入构造函数**而非事后赋值，避免异步环境下 `note.tags = tags` 触发同步惰性加载（`MissingGreenlet`）。
2. **统一响应包裹**：`schemas/common.ok()` 产出 `{code, message, data}`，前端 `unwrap()` 对称解包。
3. **统计写时对账**：`user_garden_stats` 在 AI 完成/删除/复习时 `recalc_stats` 重算，不依赖增量累计（避免漂移）。
4. **优雅降级**：`_get_llm()` / `_get_vector_store()` 均 try/except 返回 None，流水线每步独立容错；前端显示 `processing_status=failed` 并允许"重新处理"。
5. **调度任务**：`scheduler_loop` 每小时扫 `wilted`（超过 `WILT_DAYS` 未复习置枯萎）；每天尝试一次"每日关联发现"（需 ChromaDB，不可用自动跳过）。
6. **认证**：`deps.get_current_user` 校验 Bearer JWT；`security` 使用 bcrypt 哈希密码。

### 7.3 前端联调对齐点

- 前端 `unwrap()` 依赖后端 `code===0` 与 `data` 字段；错误透传 `detail`。
- 时间/日期字段为 ISO 字符串（`DateTime(timezone=True)` / `Date`），前端 `utils/format` 统一格式化。
- 标签名 ↔ `TagOut` 往返：前端发送标签名数组，后端 `resolve_tags` 幂等创建/复用并回传带 id/color 的对象。

## 8. 关键实现细节与踩坑记录

> 这些坑后续改动时大概率还会遇到，务必先看这里。

### 8.1 端口 8000 被系统进程占用 → 统一改用 8011

- **现象**：uvicorn 启动报 `WinError 10013`（以一种访问权限不允许的方式访问套接字）。
- **根因**：本机 8000 端口被名为 `Manager` 的系统进程监听（`netstat -ano` 确认 PID）。
- **处理**：后端固定使用 **8011**，前端 Vite 代理 `target: http://localhost:8011`，`backend/start.bat` 同步。**切勿改动后忘记同步三处**（vite.config.ts / start.bat / README）。

### 8.2 SQLAlchemy 异步 MissingGreenlet

- **现象**：`note.tags = tags` 抛 `MissingGreenlet: greenlet_spawn has not been called`。
- **根因**：给未加载的关系属性赋值时，ORM 会先同步惰性加载旧集合；async 环境下不允许同步 IO。
- **处理**：
  - 新建笔记：先 `resolve_tags`，再把 tags **传入 `Note(..., tags=tags)` 构造函数**；
  - 已有笔记：查询时显式 `.options(selectinload(Note.tags))` 预加载；
  - AI 流水线内加载笔记同样加 `selectinload`。

### 8.3 修复的原有用例缺陷

| 文件 | 问题 | 修复 |
|---|---|---|
| `models/relation.py` | 使用 `String` 未导入 → `NameError` | 补充 `String` 导入 |
| `schemas/note.py` | 缺少 `ReprocessResult` 模型 | 新增（与 `NoteCreateOut` 同构） |

### 8.4 Windows 环境专项

- **控制台乱码**：npm/Vite/uvicorn 输出为 UTF-8，Windows 控制台默认 GBK(936)。解决：`chcp 65001`、或用 VS Code/Windows Terminal、或双击 `frontend/dev.bat` / `backend/start.bat`（已内置 `chcp 65001`）。
- **`python` 命令是 Store 别名**：`python -m venv` 静默失败。改用 `py -3 -m venv` 创建虚拟环境。
- **pip 安装报 GBK 解码错误**：`UnicodeDecodeError: 'gbk' codec can't decode`。解决：设置环境变量 `PYTHONUTF8=1` 后重跑 `pip install`。

## 10. 运行与部署

### 10.1 本地开发（Windows 推荐）

```cmd
:: ① 基础设施（Docker 容器，无需手动装 PG/Redis）
docker compose up -d postgres redis chromadb

:: ② 后端（双击 backend\start.bat 或）
cd backend
py -3 -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8011

:: ③ 前端
cd frontend
npm install
npm run dev        # http://localhost:5173
```

### 10.2 Docker Compose 全栈

```bash
docker compose up -d --build
# 前端 http://localhost:80 / 后端 http://localhost:8000/docs
```
> 注意：若本机 8000 被占用，需修改 `docker-compose.yml` 中 backend 的宿主机端口映射。

### 10.3 开启 AI 能力

AI 功能默认走 **DeepSeek 云端**（`backend/.env` 中配置 `DEEPSEEK_API_KEY`，模型 `deepseek-v4-flash`），无需本地安装。

如需切换本地 Ollama（`LLM_PROVIDER=ollama`），先安装模型：

```bash
ollama pull qwen2.5:7b && ollama pull bge-m3
```

嵌入模型固定使用 bge-m3；LLM 未配置时系统优雅降级（§3.3）。
